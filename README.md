# 値動きウォッチ フェーズ8-5試作(GUI化・ほぼ完了)

「株価確認ツール要件定義書」のフェーズ1〜8-5に対応する、
Pythonの学習も兼ねたシンプルなプログラムです。

yfinance(米国版Yahoo Finance経由のライブラリ)から株価データを取得し、
折れ線グラフを表示します。これまでのターミナル上の「メニュー」形式
(`python main.py`)に加えて、フェーズ8からはブラウザで見られるGUI版
(`python app.py`)を段階的に用意してきましたが、フェーズ8-5で
ターミナル版の全15メニューがGUI版でも一通り使えるようになりました
(ウォッチリスト表示・比較グラフ・銘柄の表示非表示切り替え・銘柄の
追加削除・実額表示とソロ表示・用語集/用語検索・関連ニュース・詳細
チャート・値動き予測)。ターミナル版・GUI版のどちらから操作しても
共通のファイル(`watchlist.json`・`data/`フォルダ)を読み書きするので、
両方を使い分けても内容は同じです。

コードには初心者向けにコメントを多めに書いています。

**開発の経緯(参考)**: 最初はstooq.comというサイトから直接データを取得していましたが、
実際に動かしたところ、stooq側の「プログラムからの自動アクセスをブロックする対策」に
引っかかり、安定して取得できないことが分かりました。そこで、株価データ取得用の
Pythonライブラリとして広く使われている「yfinance」に切り替えています。
yfinanceはAPIキーなどの登録が不要です。

## セットアップ手順

### 1. 仮想環境(venv)を作る

お使いの環境によっては、Pythonのライブラリをシステム全体に直接インストールできない
制限がかかっていることがあります。その場合に備えて、このプロジェクト専用の
「仮想環境」を作ってから進めるのが安全です(すでに作成済みの場合は不要です)。

VS Codeでこのフォルダを開き、ターミナル(メニューの「表示」→「ターミナル」)で
次のコマンドを順番に実行してください。

```
python3 -m venv venv
source venv/bin/activate
```

2つ目のコマンドを実行すると、ターミナルの行の先頭に `(venv)` と表示されます。
これが出ていれば、仮想環境が有効になっている状態です(以後、ターミナルを開き直す
たびに `source venv/bin/activate` を再実行してください)。

### 2. 必要なライブラリをインストールする

`(venv)` が表示された状態のターミナルで、次のコマンドを実行してください。

```
pip install -r requirements.txt
```

※ フェーズ8からGUI版(Web版)を追加したことにより、`flask`という
  ライブラリが新しく必要になりました。以前からこのツールを使っている
  場合は、このコマンドを再度実行して`flask`を追加インストールして
  ください(Windowsで`pip`が認識されない場合は`python -m pip install -r requirements.txt`)。

### 3. 実行する(ターミナル版)

同じターミナルで次のコマンドを実行してください。

```
python main.py
```

初回実行時は、`watchlist.json` が自動的に作られ、基本の2指数+組み込み済み
12社が登録された状態で始まります。実行すると、次のようなメニューが表示されます。

```
==================================================
値動きウォッチ フェーズ7 - メニュー
==================================================
1: ウォッチリストを表示する
2: 銘柄を追加する
3: 銘柄を非表示にする
4: 非表示中の銘柄を再表示する
5: 銘柄を削除する(完全に削除・元に戻せません)
6: データを取得してグラフを表示する
7: 表示期間を変更する(現在: 1年)
8: 表示モードを変更する(現在: 変化率)
9: 1つの銘柄だけを表示する(ソロ表示・実額表示への切り替えに便利)
10: 全ての銘柄を表示に戻す
11: 用語集を表示する
12: 用語を検索する
13: 関連ニュースを表示する
14: 詳細チャートを表示する(ローソク足・移動平均線・出来高)
15: 値動き予測を表示する(参考情報・売買シグナル付き)
0: 終了する
--------------------------------------------------
番号を選んでください:
```

数字を入力してEnterキーを押すと、それぞれの操作ができます。基本的な流れは、

1. 「2」で見たい銘柄を追加する(証券コード、またはティッカーシンボルを入力)
2. 「6」でデータを取得し、グラフを表示する

です。グラフは `chart.png` としても保存されるので、ウィンドウがうまく開かない
場合はこの画像ファイルをVS Code上でクリックして確認してください。

※ フェーズ3から、初回のデータ取得時にさかのぼる期間を(5年分の表示に対応
  するため)約5年分に広げました。そのため、初回の「6」実行時は以前より
  少し時間がかかることがあります。

### 3'. 実行する(GUI版・Web版、フェーズ8-1)

ブラウザで見られるGUI版を試す場合は、代わりに次のコマンドを実行します。

```
python app.py
```

起動したら、ブラウザで `http://127.0.0.1:5000` を開いてください。
詳しくは後述の「フェーズ8: GUI(Web)版について」をご覧ください。

### 表示期間・表示モードの切り替えについて(フェーズ3・7.3節)

- **「7: 表示期間を変更する」**:1ヶ月/3ヶ月/6ヶ月/1年/5年から選べます。
  選んだ期間は、次に「6」でグラフを表示するときに使われます。
- **「8: 表示モードを変更する」**:通常は「変化率(%)」(期間の始点を0%とした
  変化率で、複数の銘柄を公平に比較できる)ですが、表示中の銘柄がちょうど1つ
  だけのときに限り、「実額」(円やptなど、そのままの値)表示にも切り替えられます。
  表示中の銘柄が2つ以上あるときに実額を選ぼうとすると、値の単位がバラバラで
  比較にならないため、選べないようにしています。
- 表示期間・表示モードの設定は、プログラムを終了すると既定値(1年・変化率)に
  戻ります(ファイルには保存していません)。

### グラフの色について

各指数・銘柄には、それぞれ専用の色が1つ決まっており、`watchlist.json` に
保存されています。銘柄を非表示にしたり追加したりして表示順が変わっても、
同じ会社は常に同じ色でグラフに描かれます(以前は、matplotlib(グラフ描画
ライブラリ)が「表示されている順番」に沿って自動で色を割り振っていたため、
表示順が変わるたびに同じ会社でも色が変わってしまう問題がありました)。

新しく追加した銘柄には、まだ使われていない色が自動的に割り当てられます。
色の一覧は `watchlist.py` の `COLOR_PALETTE` で確認・変更できます(最大17色分
用意してあり、基本の2指数+個別銘柄15社の合計17件をすべて別の色にできます)。

### 「9: ソロ表示」について(実額表示を使うために)

「8: 表示モードを変更する」で「実額」を選べるのは、表示中の銘柄が
**ちょうど1つ**のときだけです。これは仕様上の制限で、理由は次の通りです。

日経平均(数万pt)のような指数と、キーコーヒーの株価(数千円)のような
個別銘柄とでは、値の大きさ(スケール)が大きく違います。これらを「実額」の
まま同じグラフに重ねて描くと、値の小さい方のグラフがほぼ0円の位置に
張り付いてしまい、値動きがまったく見えなくなってしまいます。
そのため、複数の銘柄を比べるときは、期間の始点を0%とした「変化率(%)」で
揃えるのが基本の考え方です(要件定義書2.4節)。実額での表示は、
1つの銘柄の値動きをそのままの単位で細かく見たいときのための機能、
という位置づけになっています。

以前は、複数登録している状態から実額表示に切り替えるには、見たい1件を
残して他の銘柄を「3: 銘柄を非表示にする」で1つずつ非表示にする必要があり、
登録数が多いと手間がかかりました。「9: 1つの銘柄だけを表示する(ソロ表示)」は、
一覧から見たい1件を選ぶだけで、それ以外をまとめて非表示にできる
ショートカット機能です。もとに戻したいときは「10: 全ての銘柄を表示に戻す」を
使ってください(どちらも「非表示」を切り替えているだけなので、データや
登録情報が消えることはありません)。

### 「1: ウォッチリストを表示する」の前日比表示について(フェーズ4・7.4節)

**確認方法**:①まず「6: データを取得してグラフを表示する」を一度実行して
データを取得し、②そのあとで「1: ウォッチリストを表示する」を選んでください。
各銘柄の下に「前日比」(前の取引日の終値と比べていくら変わったか・%も表示)が
表示されます。上昇は赤、下落は青で色分けしています(日本の株価表示でよくある
配色です)。

一度「6」でデータを取得すると、その結果は`data/`フォルダにCSVとして保存される
ため、次に「1」を選んだときは(プログラムを終了して再起動していても)
あらためて「6」を実行しなくても前日比が表示されます。まだ一度も「6」を
実行していない銘柄だけ「(データ未取得)」と表示されます。

※ 色付き表示にはターミナルの機能(ANSIエスケープコード)を使っています。
  VS Codeのターミナルであれば問題なく色が表示されますが、環境によっては
  色が付かず記号のような文字列がそのまま表示されることがあります。
  その場合はお知らせください。

### 「11: 用語集を表示する」「12: 用語を検索する」について(フェーズ4・7.4節・7.7節)

- **「11: 用語集を表示する」**:証券コード・前日比・騰落率・移動平均線など、
  グラフや投資でよく出てくる言葉の説明を一覧表示します(要件定義書 第4章の
  用語集がもとになっています)。
- **「12: 用語を検索する」**:キーワードを入力すると、用語の名前だけでなく
  説明文の中も検索し、一致した用語とその説明を表示します。一致した部分は
  黄色く強調表示されます。

### 「13: 関連ニュースを表示する」について(フェーズ5・7.6節)

表示中の銘柄について、関連ニュース(見出し・配信元・日時・リンク)を
新しい順にまとめて表示します。番号で1銘柄だけを選ぶことも、「0」で
表示中の銘柄すべてのニュースをまとめて見ることもできます。各ニュースの
先頭には、その銘柄名を示すタグが付き、グラフの線と同じ色で表示されます
(会社ごとに色が固定されているのはフェーズ3の変更点と同じ仕組みです)。

**ニュースの取得元について(v0.14で変更)**:最初はyfinance内蔵のニュース機能
(Yahoo Finance米国版経由)を使っていましたが、配信元が英語圏中心のため、
日本語のニュースがほとんど表示されないという問題がありました。そこで、
Googleニュースが無料で公開している「検索結果のRSS配信」という仕組みに
切り替え、銘柄名で検索したニュースを日本語・日本向け設定で取得するように
しました。RSSはもともと第三者が購読・表示することを想定した公開の仕組み
なので、アカウント登録やAPIキーの発行は不要です(以前問題になった
stooq.comのブロック対策や、Yahoo!ファイナンス(日本版)の利用規約とは
性質が異なります)。Pythonの標準ライブラリだけで実装しているため、新しく
インストールするライブラリもありません。

**「やさしい解説」について(対応しないことを確定・v0.17)**:要件定義書7.6節では、
各ニュースに初心者向けの言い換え解説を付けることを想定していましたが、これを
自動生成するには別途AIサービスとの連携(登録・費用)が必要になります。ご相談の結果、
この自動生成機能は追加せず、見出し・配信元・日時・リンクの一覧表示までとすることに
確定しました。ニュースの中に分からない言葉が出てきたら、「12: 用語を検索する」で
調べてみてください。

### 「14: 詳細チャートを表示する」について(フェーズ6・7.3節・11章)

1つの銘柄を選んで、ローソク足チャート・移動平均線・出来高をまとめて
表示する機能です。要件定義書11章でご指定いただいた優先順(ローソク足→
移動平均線→出来高)に沿って実装しています。

- **ローソク足**:1本ごとに、その日の始値・高値・安値・終値を表します。
  終値が始値より高い日(陽線)は赤、低い日(陰線)は青で表示します
  (要件定義書3.2節・前日比の色分けと同じ考え方です)。上下に伸びる細い線
  (ヒゲ)が、その日の高値・安値を表します。
- **移動平均線**:銘柄を選んだあとに「表示しますか?(y/n)」と聞かれます。
  「y」を選ぶと、25日移動平均線(直近25日分の終値の平均をつないだ線)を
  オレンジ色で重ねて表示します。
- **出来高**:下段に棒グラフで表示します。ローソク足と同じく、陽線の日は
  赤、陰線の日は青にしています。

表示期間は「7: 表示期間を変更する」で設定した期間がそのまま使われます。
このメニューを選ぶと、まずその銘柄のデータを最新に取得し直してから
表示します(「6」と同様の取得処理です)。

なお、ローソク足は1つの銘柄をじっくり見るためのグラフのため、複数銘柄を
比較する「6」のグラフ(折れ線・変化率または実額)とは別の画面として
実装しています。両方を使い分けてご覧ください。

### 「15: 値動き予測を表示する」について(フェーズ7・7.9節)

1つの銘柄を選ぶと、「過去に似たような値動きをしたことがあるか」を
自動的に探し、その後どうなったかをもとにした「予測ライン」(確率の高い順に
上位3本)と、参考の「売買シグナル」を表示する機能です。**AIサービスは
一切使っておらず**、Pythonの標準的な計算だけで実装しています。

**算出の考え方(かんたんに)**

1. 直近20営業日分について、(a)値動き(変化率)と、(b)25日移動平均線からの
   乖離率(終値が移動平均線からどれだけ離れているか)の2つを組み合わせて
   「今のパターン」とする(v0.17より。ご指定により出来高は組み合わせていません)。
2. その銘柄の過去データ全体から、同じ長さのパターンを1日ずつずらしながら
   すべて比較し、(a)(b)の両方の形が近いものを探す。
3. 似ている順に、開始日が近すぎないものを選びながら、代表的な3パターンを選ぶ。
4. 選んだ3パターンについて、「そのあと10営業日でどう動いたか」を、
   現在の株価に当てはめたものを「予測ライン」としてグラフに重ねて表示する。
5. 確率(参考値)は、似ている順の上位30パターンのうち、「上昇・下降・横ばい」の
   同じ分類に入ったものの割合(%)を計算したもの。
6. 売買シグナルは、3パターンを確率で重み付けした平均的な方向から、
   「買い時の目安」「売り時の目安」「様子見」を参考として表示する。

画面には、実行するたびに必ず次の注意書きを表示します。

> ※ 過去の似た値動きパターンをもとにした統計的な参考情報です。将来の値動きを
>   保証するものではなく、投資判断の根拠として使わないでください。

**なぜこの方式にしたか**:要件定義書7.9節では「移動平均線・ボリンジャーバンド・
出来高などを組み合わせた予測」「確率の高い順に上位3本」「売買シグナル」を
将来フェーズの要件としつつも、具体的な算出方法は「着手時に検討する」として
あえて決めていませんでした(13章)。AIサービスとの連携は費用が発生するため
使わない方針(これまでのニュース機能と同じ考え方)とし、代わりに「過去の
似たパターン探し(統計的な頻度集計)」というシンプルで無料・実装可能な方式を
採用しています。v0.16では値動き(変化率)だけで似ているかどうかを判定して
いましたが、v0.17でご指定により移動平均線からの乖離率も組み合わせ、値動きの
形だけでなく「移動平均線から見て今どのくらい離れているか」も加味した判定に
拡張しました(出来高は組み合わせていません)。確率はあくまで「過去に似た
パターンがどうなったかの頻度」であり、将来を予測・保証するものではありません。

### 銘柄の追加について

「2: 銘柄を追加する」を選ぶと、証券コード(日本株、例: `7203`)または
ティッカーシンボル(米国株、例: `AAPL`)の入力を求められます。日本株は
4桁の数字を入力するだけで、自動的に東証向けのシンボル(`7203.T`)に変換されます。

会社名はyfinanceが自動で調べてくれますが、「市場区分」と「事業内容」は
yfinanceからは正確に取得できないため、追加のたびに手入力する形にしています
(分からなければ空欄のままでも登録できます)。

個別銘柄は最大15社まで登録できます(基本の2指数とは別枠です)。

### 非表示・削除の違いについて

- **非表示にする(メニュー3)**:グラフや一覧から一時的に隠すだけで、データや
  登録情報は消えません。「4: 非表示中の銘柄を再表示する」でいつでも戻せます。
  基本の2指数(日経平均・NASDAQ)も非表示にはできます。
- **削除する(メニュー5)**:ウォッチリストから完全に取り除きます。元に戻すには
  もう一度「2」で追加し直す必要があります。基本の2指数は削除できない仕組みに
  しています(要件定義書 7.8節)。

### 用語集・ニュース・詳細チャート・値動き予測について(フェーズ8-5)

フェーズ8-5で、ターミナル版に残っていた最後の4機能をまとめてGUI化
しました。それぞれの考え方・算出方法は、上のターミナル版の説明
(「11: 用語集を表示する」〜「15: 値動き予測を表示する」の各節)と
まったく同じで、GUI版では次のように操作できます。

- **用語集・用語検索**:ページを開くと自動的に全19件の用語が表示され
  ます。キーワードを入力して「検索する」を押すと、用語名・説明文の
  どちらかに一致するものだけに絞り込まれ、一致した部分が黄色く
  ハイライト表示されます。「検索をクリア」で全件表示に戻ります。
- **関連ニュース**:プルダウンで銘柄を1つ選ぶか「表示中の銘柄すべて」を
  選んで「ニュースを取得する」を押すと、新しい順にニュース(見出し・
  配信元・日時)が一覧表示されます(見出しはリンクになっており、元の
  記事を開けます)。各ニュースの先頭には、その銘柄名を示すタグが
  グラフの線と同じ色で表示されます。非表示中の銘柄はプルダウンの
  一覧にも出てきません(ターミナル版と同じ仕様です)。
- **詳細チャート**:プルダウンで銘柄を1つ選び、「25日移動平均線を
  表示する」のチェックの有無を選んでから「データを取得して表示する」を
  押すと、ローソク足チャート・出来高のグラフが画像として表示されます。
  表示期間は、上の「表示期間」の設定がそのまま使われます。
- **値動き予測**:プルダウンで銘柄を1つ選んで「データを取得して予測を
  表示する」を押すと、予測パターン(確率・方向・目安株価)の一覧、
  売買シグナル(参考情報)、予測ラインを重ねたグラフが表示されます。
  データが少なすぎて似たパターンが見つからない場合は、その旨の
  メッセージが表示されます。

これらのグラフ画像(ローソク足チャート・値動き予測チャート)は、
比較グラフ(折れ線)とは異なり、これまでターミナル版で使っていた
matplotlib(グラフ描画ライブラリ)の描画処理をサーバー側でそのまま
再利用し、画像(PNG)として生成してブラウザに送る方式にしています。
複雑なローソク足・予測ラインの描画ロジックをJavaScriptで新たに
作り直す必要がなく、ターミナル版とまったく同じ見た目のグラフが
GUI版でも表示されます。

### 起動方法(パソコンから直接)

```
python app.py
```
と実行してから、ブラウザで `http://127.0.0.1:5000` を開いてください
(`Ctrl+C`で終了します)。

### デスクトップのアイコンをクリックして起動する設定(Linux)

今お使いのパソコン(Linux)向けの手順です。

1. ターミナルで次を実行して、起動スクリプトに実行権限をつけます。
   ```
   chmod +x start_app.sh
   ```
2. `値動きウォッチ.desktop` ファイルを、デスクトップ
   (`~/Desktop`)または `~/.local/share/applications/` に置きます。
3. デスクトップに置いた場合、初回はファイルを右クリックして
   「起動を許可する」(Allow Launching)のような項目を選ぶ必要があります
   (GNOME/Nautilusでは、知らない`.desktop`ファイルをそのままでは実行
   できない安全のための仕組みです)。
4. 以降は、そのアイコンをダブルクリックするとWebアプリが起動し、
   自動的にブラウザで開きます。すでに起動している場合は、ブラウザを
   開くだけです。

もしアイコンをクリックしても起動しない場合は、`値動きウォッチ.desktop`
の中の`Exec=`の行が、実際にこのツールを置いてあるフォルダのパスに
なっているか確認してください。

### アプリの終了について(ブラウザを閉じると自動終了・v0.26)

デスクトップのアイコンから起動した場合、Webアプリは裏側(バック
グラウンド)で動き続けるため、以前は終了させるのに
```
pkill -f "python3 app.py"
```
をターミナルで実行する必要がありました。「ブラウザを閉じたら自動で
終わってほしい」というご要望を受けて、v0.26より次の仕組みを追加し、
手動での終了操作は基本的に不要になりました。

- ブラウザがページを開いている間、画面側(script.js)が3秒おきに
  サーバーへ「まだ使っています」の合図(heartbeat)を送ります。
- サーバー側は、この合図が10秒以上途絶えると「ブラウザが閉じられた」
  とみなし、自動的にアプリを終了します。タブを閉じる・ブラウザ全体を
  閉じる・パソコンをシャットダウンする、いずれの場合も、閉じてから
  10〜15秒ほどでアプリが自動的に終了します。
- 複数のタブ・ウィンドウでこのアプリを開いている場合は、すべて閉じた
  ときに初めて終了します(どれか1つが開いていれば動き続けます)。
- 起動直後、まだブラウザで一度も開いていない間は、この自動終了の
  判定は行いません(ブラウザを開く前に誤って終了しないようにするため)。

なお、何らかの理由でこの自動終了がうまく働かない場合に備えて、
これまで通り`pkill -f "python3 app.py"`で手動終了することもできます
(`ps aux | grep "app.py"`で、動いているかどうかを確認できます)。

### スマートフォン対応について(今後の予定)

フェーズ8は「まずパソコンのブラウザで動くGUI版を作る」ところから始めて
います。要件定義書8章にある「PWA化」(スマートフォンのホーム画面に

### 技術的な補足:グラフを外部ライブラリなしで描画している理由

比較グラフは、Chart.jsなどの外部のグラフ描画ライブラリを使わず、
ブラウザ標準の`<canvas>`という仕組みだけで自前で描画しています。これは
本ツールがこれまで大切にしてきた「外部サービス・ライブラリへの依存を
できるだけ減らす」という考え方(9章:ニュース機能をGoogle News RSSだけで
作った判断、13章:予測機能をAI・有料APIなしで作った判断と同じ考え方)を
GUI版にも引き継いだものです。インターネット接続が不安定なときや、
社内ネットワークの制限などで外部のCDN(ライブラリ配信サーバー)に
アクセスできない環境でも、グラフ自体は問題なく表示されます。

### 更新履歴(v0.20:実データでの動作確認時に見つかった不具合の修正)

実際のパソコンで実銘柄構成(米国株のNVIDIA等を含む)を使ってフェーズ8-1を
お試しいただいたところ、次の2件が見つかり、修正しました。

- **ツールチップに表示銘柄すべての数値が一度に出て見づらい**:マウスの
  縦位置から、カーソルが指している1本の線を判定し、その銘柄名・数値だけを
  表示するように変更しました。

### 実額表示・ソロ表示について(フェーズ8-4)

「表示モード」のプルダウンで「実額」を選ぶと、変化率(%)ではなく、
その銘柄の実際の値(円・ptなど)でグラフを描きます。日経平均(数万pt)と
キーコーヒーの株価(数千円)のように単位がバラバラな銘柄を実額のまま
重ねると、値の小さい方がほぼ見えなくなってしまうため、ターミナル版と
同じく「表示中の銘柄がちょうど1つ」のときだけ選べる仕様です。それ以外の
ときは「実額」の選択肢がグレーアウトし、下に理由を表示します。

複数登録している状態から1つに絞るには、ウォッチリストの各行にある
「ソロ表示」リンクを使うと便利です。押した銘柄だけが表示中になり、
それ以外は自動的に非表示になります(ターミナル版のメニュー「9」と
同じ処理)。データが消えるわけではないので、「全ての銘柄を表示に戻す」
ボタンを押せばいつでも元の状態(全件表示)に戻せます(ターミナル版の
メニュー「10」と同じ処理)。

実額表示では、その銘柄の単位(¥・$・pt)を、グラフのタイトルと、
縦軸の左上(v0.27より、目盛り1つ1つにではなく1回だけ)、カーソルを
合わせたときのツールチップに表示します。日本株は「¥」、米国株は
「$」、指数(日経平均・NASDAQ)は「pt」(ポイント。円やドルでは
ありません)と表示されます。縦軸の目盛りの数値には、1,000円のような
大きな値でも読みやすいよう、3桁ごとの区切り(カンマ)を付けています。

### 更新履歴(v0.29:フェーズ8-5の不具合修正 詳細チャート表示後にアプリ全体が反応しなくなる問題)

実際にご自身のパソコン(画面表示のあるデスクトップ環境)でフェーズ8-5を
お試しいただいたところ、「詳細チャートで銘柄を変更すると『チャートの
表示に失敗しました。通信状況を確認してください。』と表示され、その後は
値動き予測も関連ニュースも反応しなくなる」という不具合が見つかり、
修正しました。

- **原因**:グラフ描画ライブラリ(matplotlib)は、特に何も指定しないと、
  そのパソコンの環境によって「画面にウィンドウを表示するための」
  GUIバックエンド(TkAggなど)を自動的に選んでしまうことがあります。
  ターミナル版(`main.py`)はグラフをウィンドウで見せる仕様のため
  これで問題ありませんが、Webサーバー版(`app.py`)は画像(PNG)を
  作ってブラウザに送るだけで、ウィンドウは不要です。むしろGUI
  バックエンドを使うと、サーバーの処理と競合してサーバー全体が
  固まってしまうことがあります。このツールの開発・自動テストは
  画面表示のない環境(サーバー)で行っていたため、matplotlibが
  自動的に画面表示なし用の安全なバックエンド(Agg)を選んでおり、
  この問題を事前に発見できませんでした。実際に画面表示のあるご自身の
  パソコンで動かして初めて再現した不具合です。
- **修正内容**:`app.py`の一番先頭(他のファイルを読み込むよりも前)で、
  matplotlibに対して明示的に「Agg」バックエンド(画面表示を行わず、
  画像の生成だけを行う安全なモード)を使うよう指定しました。この指定は
  `app.py`のプロセスの中だけで有効なため、ターミナル版
  (`python main.py`)でグラフがウィンドウ表示される動作には
  影響ありません。
- 実際に、詳細チャートで銘柄を連続して切り替えて何度も表示した後、
  値動き予測・関連ニュースが問題なく動作し続けることを確認済みです。

## うまく動かないときは

- `(venv)` がターミナルの行頭に表示されているか確認してください(消えている場合は
  `source venv/bin/activate` を再実行)。
- インターネットに接続されているか確認してください。
- 「データが取得できませんでした」が続く場合は、yfinanceのバージョンが
  古い可能性があります。次のコマンドで更新してから試してください。
  ```
  pip install --upgrade yfinance
  ```
- 銘柄追加時に「会社名を自動取得できませんでした」と出る場合は、証券コードや
  ティッカーシンボルが正しいか確認してください。
- グラフのウィンドウが開かない場合は、`chart.png`(比較グラフ)、
  `candle_chart.png`(ローソク足チャート)、`predict_chart.png`(値動き予測)を
  直接開いて確認してください。
- エラーメッセージが表示された場合は、その内容をそのまま質問してもらえれば
  一緒に確認できます。
- GUI版(`python app.py`)で、ブラウザで`http://127.0.0.1:5000`を開いても
  真っ白のまま・繋がらない場合は、`app.py`を実行しているターミナルに
  エラーが出ていないか確認してください。ポート5000がすでに他のアプリで
  使われている場合は、いったんそのアプリを終了するか、ご相談ください。
- デスクトップのアイコンをダブルクリックしても何も起きない場合は、
  「デスクトップのアイコンをクリックして起動する設定」の手順(実行権限・
  起動の許可・`Exec=`のパス)を確認してください。

## GitHubにpushする手順(ブランチ・プルリクエスト方式)

フェーズ8-3から、勉強も兼ねて「作業用のブランチを作り、プルリクエスト(PR)を
経てmainブランチに取り込む」という、実際の開発現場でよく使われる流れに変更
しました。以前のように直接mainブランチにpushする方式に比べて手順は1つ増え
ますが、「変更内容をまとめて確認してから取り込む」という感覚が身につきます。

### 初回のみ(まだ一度もpushしたことがない場合)

```
git init
git add .
git commit -m "最初のコミット"
git branch -M main
git remote add origin リポジトリURL
git push -u origin main
```

### 通常の流れ(フェーズが進むたびに、このステップを繰り返します)

1. 作業を始める前に、手元のmainブランチを最新にする

   ```
   git checkout main
   git pull
   ```

2. 今回の変更用に、新しいブランチを作って切り替える(ブランチ名は内容が
   わかる名前にする。今回の例: `feature/phase8-5`)

   ```
   git checkout -b feature/phase8-5
   ```

3. 変更をコミットする

   ```
   git add .
   git commit -m "フェーズ8-5: 用語集・ニュース・詳細チャート・値動き予測をGUI化"
   ```

4. 作ったブランチをGitHubにpushする(mainにではなく、このブランチに
   pushする点に注意)

   ```
   git push -u origin feature/phase8-5
   ```

5. ブラウザでGitHubのリポジトリページを開くと「Compare & pull request」
   というボタンが出てくるので、それを押してプルリクエスト(PR)を作成する
   (タイトル・説明を書いて「Create pull request」)。

6. PRの「Files changed」タブなどで変更内容をひと通り見て、問題なければ
   「Merge pull request」→「Confirm merge」を押してmainブランチに取り込む。

7. 手元のmainブランチを、取り込んだ内容で最新にし、使い終わったブランチを
   削除する。

   ```
   git checkout main
   git pull
   git branch -d feature/phase8-5
   ```

   GitHub上に残っているリモート側のブランチも、マージ後に出てくる
   「Delete branch」ボタンで削除できます(削除してもmainに取り込んだ内容は
   残るので安心してください)。

次のフェーズ(8-5以降)に進むときも、毎回このステップ1〜7を、ブランチ名
だけ変えて(例: `feature/phase8-6`)繰り返す形になります。

### pushする前に必ず確認してほしいこと

- `git status` を実行して、`venv/` フォルダや `data/` フォルダ、`chart.png` が
  リストに出てこないこと(`.gitignore` に登録済みなので、正しく動いていれば
  表示されません)
- もし何かの拍子に `.env` を作ってキーのような値を書いていた場合は、それも
  リストに出てこないことを確認してください
- もし誤って上記のいずれかを一度コミットしてしまった場合は、`.gitignore` に
  追加しただけでは消えません。その場合は先にこちらに相談してください
  (履歴からの削除にはコマンドの実行に注意が必要です)。
- `watchlist.json` は(秘密の情報を含まないため)あえてGitHubにpushする対象に
  しています。自分のウォッチリストの内容をバックアップしておきたい場合に便利です。

## コラム: `.env` / `.gitignore` の仕組みについて

フェーズ5のニュース表示機能は、外部のニュースAPIには登録せず、株価データと
同じyfinance経由で取得する方式にしたため、今回も秘密のAPIキーは不要でした。
`.env`ファイルは引き続き使っていません。ただし、今後もし別の外部サービス
(有料APIなど)と連携する機能を追加する場合には、そのAPIキーを安全に管理する
ために同じ仕組み(`.env`に秘密の値を書き、`.gitignore`でGitHubへの
アップロード対象から除外する)を使う想定です。そのため、`.env.example` と
`.gitignore` のファイルはこのまま残してあります。
